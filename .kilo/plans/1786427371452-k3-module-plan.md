# Plan: K3 Module (Prioritas 4 Fitur)

## Scope
Implement four K3 features as CRUD modules following existing SIMLABKOM patterns (Laravel resource controller, Blade views, permission middleware, sidebar sections):
1. Identifikasi bahaya, penilaian risiko, dan pengendalian risiko
2. Pengelolaan limbah B3
3. Laporan insiden K3
4. Tanggap darurat

## Affected Boundaries
- `app/Models/*` new models: `HazardIdentification`, `B3Waste`, `IncidentReport`, `EmergencyResponse`
- `app/Http/Controllers/*` new resource controllers
- `database/migrations/*` new tables
- `routes/web.php` resource routes with permission middleware
- `resources/views/k3/*` index/create/edit/show/print views
- `resources/views/layouts/app.blade.php` sidebar section `K3 Laboratorium`
- Permission seeders/role permissions if applicable

## Data Design (initial)
### HazardIdentification
- laboratory_id (nullable FK)
- area_activity
- hazard
- risk
- likelihood_before, impact_before
- risk_level_before
- control_before
- schedule
- likelihood_after, impact_after
- risk_level_after
- control_after
- recommendation
- authority

### B3Waste
- laboratory_id (nullable FK)
- waste_name
- waste_type
- source
- quantity
- unit
- storage_method
- disposal_method
- disposal_date
- pic
- notes

### IncidentReport
- laboratory_id (nullable FK)
- incident_date
- reporter_name
- incident_type
- description
- impact
- immediate_action
- follow_up
- status
- attachment_path

### EmergencyResponse
- laboratory_id (nullable FK)
- scenario
- procedure
- responsible_person
- contact
- equipment
- drill_date
- notes

## Implementation Steps
1. Create migrations and models with fillable fields and laboratory relation.
2. Create resource controllers with validation and pagination.
3. Register routes under permission middleware (`view-k3-hazard`, etc.).
4. Create Blade views consistent with existing modules.
5. Add sidebar entries under `K3 Laboratorium` section.
6. Add permissions to role/permission seeder or admin UI.
7. Add print views where useful (especially hazard identification table).
8. Validate with lint/tests and manual smoke test.

## Validation
- `php artisan migrate`
- `php artisan route:list`
- `php artisan test` (if available)
- Manual CRUD smoke test for each module
- Print preview for hazard identification
